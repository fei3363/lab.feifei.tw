💡 什麼是數字型 SQL Injection？

在上一課中，我們學到字串型參數需要用單引號 ' 包住。

但如果參數是數字，SQL 語法中就不需要單引號！

這代表攻擊者可以直接注入 SQL 指令，不需要處理單引號的問題。

📋 情境：商品查詢系統

💼 業務場景

網站有一個商品查詢功能，使用者可以透過商品 ID 查詢商品詳情。

例如：http://shop.com/product?id=1

🔄 字串型 vs 數字型參數

字串型參數（需要單引號）
SELECT * FROM users WHERE username = 'admin'
字串必須用單引號包住
⬇️ VS ⬇️
數字型參數（不需要單引號）
SELECT * FROM products WHERE id = 1
數字不需要單引號！

⚠️ 為什麼數字型更危險？

因為不需要處理單引號，攻擊者可以直接注入 SQL 語法！

  • ✗ 不需要用單引號「閉合」字串
  • ✗ 不需要處理跳脫字元
  • ✓ 可以直接加入 AND、OR、UNION 等關鍵字

🎯 攻擊範例 1：使用 OR 繞過條件

🚨 攻擊思路

攻擊者想要查看所有商品，而不只是某一個。

他可以注入 OR 1=1 來讓條件永遠為真。

步驟 1：原始 SQL 模板
SELECT * FROM products WHERE id = 使用者輸入
➡️
步驟 2：注入 1 OR 1=1
SELECT * FROM products WHERE id = 1 OR 1=1
➡️
步驟 3：實際執行
SELECT * FROM products WHERE id = 1 OR 1=1

結果：因為 1=1 永遠為真，會選出所有商品！

🎯 攻擊範例 2：使用 AND 加入額外條件

🚨 攻擊思路

攻擊者想要找出價格大於某個值的商品。

他可以注入 AND price > 1000 來加入額外條件。

  • 探測資料表結構（例如測試 AND column_name IS NOT NULL）
  • 加入額外的過濾條件
  • 進行資料探勘

🎯 攻擊範例 3：使用註解符號

🚨 攻擊思路

如果 SQL 查詢後面還有其他條件，攻擊者可以用註解符號把它們「註解掉」。

假設原始 SQL 是：WHERE id = ? AND status = 'active'

點擊「執行攻擊」查看 SQL 指令

💡 原理說明

假設原本的 SQL 是：

SELECT * FROM products WHERE id = ? AND status = 'active'

注入 1 OR 1=1 -- 後變成：

SELECT * FROM products WHERE id = 1 OR 1=1 -- AND status = 'active'

-- 後面的內容都被註解掉了！

🌍 真實世界的數字型 SQL Injection

⚠️ 常見的脆弱點

數字型 SQL Injection 常見於：

  • 商品查詢：product.php?id=1
  • 文章頁面：article.php?id=123
  • 使用者資料：profile.php?user_id=5
  • 分類瀏覽：category.php?cat_id=2

🔍 如何測試網站是否有數字型 SQL Injection？

測試步驟：

  1. 正常存取：product.php?id=1 → 正常顯示商品
  2. 測試加法：product.php?id=1+0 → 如果還是顯示同樣商品，可能有漏洞
  3. 測試減法：product.php?id=2-1 → 如果顯示 ID=1 的商品，確定有漏洞
  4. 測試 OR：product.php?id=1 OR 1=1 → 如果顯示多個商品，確定可以注入

✅ 如何防禦數字型 SQL Injection？

1. 使用 Prepared Statement（最重要！）

// 不安全 ❌
String sql = "SELECT * FROM products WHERE id = " + id;

// 安全 ✅
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM products WHERE id = ?"
);
stmt.setInt(1, id);

2. 型別驗證

// 確保輸入是整數
if (!is_numeric($id) || $id != (int)$id) {
    die("無效的 ID");
}
// 或使用強型別轉換
$id = (int) $_GET['id'];

3. 白名單驗證

// 確保只包含數字
if (!preg_match('/^[0-9]+$/', $id)) {
    die("無效的 ID");
}

4. 使用 ORM 框架

現代 ORM 框架會自動處理參數化查詢，大幅降低 SQL Injection 風險。
