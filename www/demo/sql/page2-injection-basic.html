🚨 什麼是 SQL Injection？

SQL Injection (SQL 注入) 是一種網路攻擊手法，攻擊者透過輸入特殊字元，改變原本的 SQL 指令邏輯，進而：

  • 🔓 繞過登入驗證
  • 📊 竊取資料庫資料
  • 🗑️ 刪除或修改資料
  • 💀 甚至控制整個資料庫

💣 步驟 2：不安全的字串拼接

⚠️ 危險的程式碼

很多開發者會用字串拼接的方式產生 SQL 指令：

// 不安全的寫法 ❌
String sql = "SELECT * FROM users WHERE username = '" + username + "' AND password = '" + password + "'";

這種寫法會讓攻擊者有機可乘！

使用者輸入
帳號：admin
密碼：password123
➡️
字串拼接
組合成 SQL 指令
➡️
最終 SQL
WHERE username = 'admin'
AND password = 'password123'

🎯 步驟 3：SQL Injection 攻擊實作

🚨 攻擊者的想法

攻擊者發現系統使用字串拼接，所以想辦法「破壞」SQL 指令的結構。

只要在輸入中加入單引號 '，就可以「提前結束」字串，然後注入自己的 SQL 指令！

💡 攻擊分析

讓我們一步步看看字串拼接的過程：

步驟 1：原始 SQL 模板
SELECT * FROM users WHERE username = '使用者輸入' AND password = '使用者輸入'
➡️
步驟 2：使用者輸入 admin' --
SELECT * FROM users WHERE username = 'admin' --' AND password = '隨便輸入'
➡️
步驟 3：字串被提前結束！
SELECT * FROM users WHERE username = 'admin' -- ' AND password = '隨便輸入'

• admin - 正常的帳號
• ' - 提前結束字串
• -- - SQL 註解符號，後面的都被忽略了！
➡️
步驟 4：實際執行的 SQL
SELECT * FROM users WHERE username = 'admin'

❌ 密碼驗證被完全略過了！

🔥 步驟 4：更多 SQL Injection 範例

⚠️ 常見的 SQL Injection 技巧

除了使用 -- 註解，攻擊者還有很多其他手法：

範例 1：使用 OR 條件繞過驗證

點擊按鈕查看 SQL 指令

💡 原理說明

注入的 SQL 變成：

SELECT * FROM users WHERE username = 'admin' OR '1'='1' AND password = '任意值'

因為 '1'='1' 永遠為真，所以 WHERE 條件一定成立！

註：實際運算優先序為 AND > OR，但這個範例仍可能繞過某些邏輯。

範例 2：使用註解符號 (另一種寫法)

點擊按鈕查看 SQL 指令

💡 原理說明

MySQL 支援多種註解符號：

  • -- (後面需要有空格)
  • #
  • /* */

這些符號都可以用來「註解掉」後面的密碼檢查。

範例 3：使用 OR 1=1 繞過

點擊按鈕查看 SQL 指令

💡 原理說明

注入的 SQL 變成：

SELECT * FROM users WHERE username = '' OR 1=1 -- ' AND password = '任意值'

因為 1=1 永遠為真，會選出資料表中的所有使用者！

✅ 如何防禦 SQL Injection？

1. 使用 Prepared Statement (參數化查詢)

// 安全的寫法 ✅
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM users WHERE username = ? AND password = ?"
);
stmt.setString(1, username);
stmt.setString(2, password);

2. 使用 ORM 框架

例如：Hibernate, Entity Framework, Django ORM 等，它們會自動處理參數化查詢。

3. 輸入驗證

檢查使用者輸入，過濾特殊字元（但這不應該是唯一的防禦手段）。

4. 最小權限原則

資料庫帳號只給必要的權限，不要使用 root 或 admin 帳號。
