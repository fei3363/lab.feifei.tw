DNS 運作細節

  • 快取機制：瀏覽器、作業系統、ISP 都會快取 DNS 記錄，加速後續查詢
  • 遞迴查詢：本機 DNS 會一層層向上查詢，從根伺服器到頂級網域再到權威伺服器
  • TTL 時間：每筆 DNS 記錄都有存活時間，過期後需重新查詢
  • 記錄類型：A 記錄（IPv4）、AAAA（IPv6）、CNAME（別名）、MX（郵件）等

TCP 連線特性

  • 可靠傳輸：保證封包順序正確，遺失會重傳
  • 流量控制：根據接收端能力調整傳送速度
  • 壅塞控制：偵測網路狀況，避免過度傳輸
  • 全雙工通訊：雙向同時傳輸資料
  • 連線導向：通訊前先建立連線，結束後釋放連線

📨 HTTP 協定基礎

HTTP 請求方法

  • GET：請求取得資源，參數放在 URL 中
  • POST：提交資料給伺服器，常用於表單送出
  • PUT：更新資源，上傳完整內容
  • DELETE：刪除指定資源
  • PATCH：部分更新資源
  • HEAD：只取得標頭資訊，不取得內容

常見狀態碼

  • 200 OK：請求成功
  • 301/302：永久/暫時重新導向
  • 400 Bad Request：錯誤的請求格式
  • 401 Unauthorized：需要驗證身份
  • 403 Forbidden：無權限存取
  • 404 Not Found：找不到資源
  • 500 Internal Server Error：伺服器內部錯誤
  • 503 Service Unavailable：服務暫時無法使用

🏗️ 常見網站架構

單體式架構 (Monolithic)

  • 特點：所有功能整合在單一應用程式中
  • 優點：開發簡單、部署方便、效能較佳
  • 缺點：難以擴展、維護困難、技術棧受限
  • 適用：小型專案、MVP 產品、團隊規模小

微服務架構 (Microservices)

  • 特點：將應用拆分為多個獨立的小服務
  • 優點：獨立部署、技術多樣性、容錯性高
  • 缺點：複雜度高、需要服務治理、網路延遲
  • 適用：大型系統、高流量網站、多團隊協作

典型三層架構

  • 前端層 (Presentation)：使用者介面、瀏覽器渲染
  • 應用層 (Application)：商業邏輯、API 伺服器
  • 資料層 (Data)：資料庫、快取、檔案儲存
  • 額外元件：負載平衡器、CDN、訊息佇列、快取層

擴展策略

  • 垂直擴展：增加單機硬體資源（CPU、記憶體）
  • 水平擴展：增加伺服器數量，透過負載平衡分散流量
  • 資料庫讀寫分離：主機寫入，從機讀取
  • 快取應用：Redis、Memcached 減輕資料庫壓力
  • CDN 加速：靜態資源分散到各地節點

⚠️ 常見攻擊面與防護

🎣 XSS 跨站腳本攻擊

攻擊方式：注入惡意 JavaScript 程式碼到網頁中

防護：輸入驗證、輸出編碼、CSP 政策、HttpOnly Cookie

💉 SQL Injection

攻擊方式：透過輸入欄位插入 SQL 指令

防護：使用參數化查詢、ORM、輸入驗證、最小權限原則

🔐 CSRF 跨站請求偽造

攻擊方式：誘使使用者在已登入狀態下執行非預期操作

防護：CSRF Token、SameSite Cookie、驗證 Referer

🚪 暴力破解

攻擊方式：大量嘗試登入，猜測帳號密碼

防護：登入限制、驗證碼、帳號鎖定、多因子認證

💥 DDoS 阻斷服務

攻擊方式：大量請求癱瘓伺服器

防護：CDN、流量清洗、限流機制、彈性擴展

🕵️ 中間人攻擊

攻擊方式：攔截和竄改通訊內容

防護：HTTPS/TLS、憑證驗證、HSTS、憑證釘扎

📂 目錄遍歷

攻擊方式：存取未授權的檔案和目錄

防護：路徑驗證、白名單、權限控制、避免暴露目錄結構

🔓 Session 劫持

攻擊方式：竊取使用者的 Session ID

防護：Secure Cookie、Session 更新、IP 綁定、逾時機制

🛡️ 資安防護最佳實踐

  • 縱深防禦：多層次安全機制，不依賴單一防護
  • 最小權限原則：只給予必要的存取權限
  • 定期更新：及時修補已知漏洞，更新套件和框架
  • 安全測試：滲透測試、程式碼審查、弱點掃描
  • 日誌監控：記錄異常行為，建立告警機制
  • 資料加密：敏感資料傳輸和儲存都要加密
  • 備份機制：定期備份，確保資料可恢復
  • 安全意識：團隊教育訓練，建立安全文化
