⚠️ AI 產碼的常見盲點

AI 生成的程式碼雖然快速方便，但常常會忽略安全性考量。以下是最常見的安全漏洞：

1. 亂用 eval() 執行不安全的程式碼

問題：AI 常常直接使用 eval() 來執行動態程式碼，這會造成嚴重的安全漏洞。

// ❌ 危險！AI 常產生這種程式碼 function calculate(userInput) { return eval(userInput); // 使用者可以輸入任何程式碼！ }
// ✅ 安全做法：使用 Function 建構子或其他安全方法 function calculate(expression) { const operators = { '+': (a, b) => a + b, '-': (a, b) => a - b, '*': (a, b) => a * b, '/': (a, b) => a / b }; // 解析並安全執行運算 }

💡 修復建議

  • 完全避免使用 eval()、new Function() 等動態執行函數
  • 改用安全的解析器或白名單機制
  • 如果真的需要，嚴格驗證和限制輸入內容

2. 缺乏輸入驗證與清理

問題：AI 產生的程式碼常常直接使用使用者輸入，沒有任何檢查。

// ❌ 危險！沒有驗證使用者輸入 app.get('/user/:id', (req, res) => { const query = `SELECT * FROM users WHERE id = ${req.params.id}`; db.query(query); // SQL Injection 漏洞！ });
// ✅ 安全做法：使用參數化查詢 app.get('/user/:id', (req, res) => { const id = parseInt(req.params.id); if (isNaN(id) || id < 1) { return res.status(400).send('無效的 ID'); } const query = 'SELECT * FROM users WHERE id = ?'; db.query(query, [id]); });

💡 修復建議

  • 所有使用者輸入都要進行型別驗證
  • 使用參數化查詢防止 SQL Injection
  • 對輸出內容進行 HTML 編碼，防止 XSS
  • 設定輸入長度和格式限制

3. 敏感資料直接寫在程式碼裡

問題：AI 會把 API 金鑰、密碼等敏感資訊直接寫在程式碼中。

// ❌ 危險！敏感資料暴露 const API_KEY = 'sk-1234567890abcdef'; const DB_PASSWORD = 'mypassword123'; const SECRET_TOKEN = 'super_secret_token';
// ✅ 安全做法：使用環境變數 require('dotenv').config(); const API_KEY = process.env.API_KEY; const DB_PASSWORD = process.env.DB_PASSWORD; const SECRET_TOKEN = process.env.SECRET_TOKEN;

💡 修復建議

  • 使用環境變數或密鑰管理服務
  • 將 .env 檔案加入 .gitignore
  • 定期輪換敏感金鑰
  • 使用密鑰管理工具（如 AWS Secrets Manager）

4. 缺乏錯誤處理與過度暴露錯誤訊息

問題：AI 產生的錯誤訊息常常包含太多系統資訊。

// ❌ 危險！暴露過多系統資訊 try { db.connect(); } catch (error) { res.send(`資料庫連線失敗: ${error.stack}`); // 洩漏系統結構！ }
// ✅ 安全做法：記錄詳細錯誤，只回傳通用訊息 try { db.connect(); } catch (error) { console.error('資料庫連線錯誤:', error); // 記錄完整錯誤 res.status(500).send('服務暫時無法使用，請稍後再試'); // 通用訊息 }

5. 缺乏權限控制和身份驗證

問題：AI 產生的 API 端點常常沒有檢查使用者權限。

// ❌ 危險！沒有權限檢查 app.delete('/admin/user/:id', (req, res) => { deleteUser(req.params.id); // 任何人都能刪除使用者！ });
// ✅ 安全做法：加入身份驗證和權限檢查 app.delete('/admin/user/:id', authenticateToken, // 驗證 token requireAdmin, // 檢查管理員權限 (req, res) => { deleteUser(req.params.id); } );
