🌐 HTTP 協定與安全防護教學

從基礎協定到暴力破解防護

📡 HTTP 協定基礎

💡 什麼是 HTTP？
HTTP (HyperText Transfer Protocol，超文本傳輸協定) 是網際網路上最常用的通訊協定。就像你跟網站「對話」的語言。

🔹 HTTP 的運作原理

1️⃣ 客戶端（瀏覽器）
發送 HTTP 請求 (Request) 到伺服器
⬇️
2️⃣ 伺服器
接收請求，處理後準備回應
⬇️
3️⃣ 伺服器
發送 HTTP 回應 (Response) 給客戶端
⬇️
4️⃣ 客戶端（瀏覽器）
接收回應，顯示網頁內容

🔹 HTTP 方法（Methods）

方法 用途 說明 範例
GET 讀取資料 從伺服器取得資料，參數放在 URL 中 /search?q=關鍵字
POST 新增資料 傳送資料到伺服器，參數放在 Body 中 提交表單、上傳檔案
PUT 更新資料 更新伺服器上的資源 修改使用者資料
DELETE 刪除資料 刪除伺服器上的資源 刪除文章
HEAD 取得標頭 只取得回應標頭，不取得內容 檢查資源是否存在
OPTIONS 查詢方法 查詢伺服器支援的方法 CORS 預檢請求

🔹 HTTP 狀態碼（Status Code）

2xx - 成功

  • 200 OK - 請求成功
  • 201 Created - 資源已建立
  • 204 No Content - 成功但無內容

3xx - 重新導向

  • 301 Moved Permanently - 永久重新導向
  • 302 Found - 暫時重新導向
  • 304 Not Modified - 資源未修改

4xx - 客戶端錯誤

  • 400 Bad Request - 請求錯誤
  • 401 Unauthorized - 未授權
  • 403 Forbidden - 禁止存取
  • 404 Not Found - 找不到資源
  • 429 Too Many Requests - 請求過多

5xx - 伺服器錯誤

  • 500 Internal Server Error - 伺服器錯誤
  • 502 Bad Gateway - 閘道錯誤
  • 503 Service Unavailable - 服務無法使用

🔹 GET vs POST 的差異

GET 請求

  • 參數放在 URL 中（Query String）
  • 參數會顯示在網址列
  • 可以加入書籤
  • 有長度限制（約 2KB）
  • 會被瀏覽器快取
  • 不適合敏感資料
GET /login?username=admin&password=123 HTTP/1.1 Host: example.com

POST 請求

  • 參數放在請求主體（Body）中
  • 參數不會顯示在網址列
  • 無法加入書籤
  • 沒有長度限制
  • 不會被快取
  • 適合敏感資料
POST /login HTTP/1.1 Host: example.com Content-Type: application/x-www-form-urlencoded username=admin&password=123

📦 HTTP 封包結構

📖 什麼是 HTTP 封包？
HTTP 封包就像是一封信，包含了「請求內容」或「回應內容」，以及各種「標頭資訊」（Header）。了解封包結構是攻防的基礎！

🔹 HTTP 請求封包結構

━━━ 請求行 (Request Line) ━━━ POST /login HTTP/1.1 ━━━ 請求標頭 (Request Headers) ━━━ Host: example.com User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Accept: text/html,application/json Accept-Language: zh-TW,zh;q=0.9,en;q=0.8 Accept-Encoding: gzip, deflate, br Content-Type: application/x-www-form-urlencoded Content-Length: 27 Cookie: session_id=abc123xyz Connection: keep-alive ━━━ 請求主體 (Request Body) ━━━ username=admin&password=123

🔹 重要的請求標頭

標頭名稱 說明 範例
Host 目標主機網域 example.com
User-Agent 客戶端資訊（瀏覽器） Mozilla/5.0...
Cookie 網站儲存的資料 session_id=abc123
Referer 來源網址 https://google.com
Content-Type 請求內容的格式 application/json
Authorization 認證資訊 Bearer token123...

🔹 HTTP 回應封包結構

━━━ 狀態行 (Status Line) ━━━ HTTP/1.1 200 OK ━━━ 回應標頭 (Response Headers) ━━━ Server: nginx/1.18.0 Date: Mon, 03 Nov 2025 10:30:00 GMT Content-Type: text/html; charset=UTF-8 Content-Length: 1234 Set-Cookie: session_id=xyz789; HttpOnly; Secure X-Frame-Options: DENY X-Content-Type-Options: nosniff Strict-Transport-Security: max-age=31536000 ━━━ 回應主體 (Response Body) ━━━ <!DOCTYPE html> <html> <head><title>登入成功</title></head> <body><h1>歡迎回來！</h1></body> </html>

🔹 重要的回應標頭

標頭名稱 說明 安全性影響
Set-Cookie 設定 Cookie 應該加上 HttpOnly, Secure 屬性
X-Frame-Options 防止被嵌入 iframe 防止點擊劫持攻擊
X-Content-Type-Options 禁止 MIME 類型嗅探 防止 XSS 攻擊
Content-Security-Policy 內容安全政策 防止 XSS 和資料注入
Strict-Transport-Security 強制使用 HTTPS 防止中間人攻擊

🔄 重送封包（Replay Attack）

⚠️ 什麼是重送封包攻擊？
攻擊者攔截合法的 HTTP 請求封包，然後重複發送這個封包來達到攻擊目的。例如：重複執行轉帳、重複投票、重複領取優惠等。 中危險

🔹 攻擊場景

常見的重送封包攻擊場景：

  1. 重複轉帳：攔截轉帳請求，重複發送造成多次扣款
  2. 重複投票：重送投票請求，灌票給特定選項
  3. 重複領取優惠：重送優惠券領取請求
  4. 繞過驗證：重送已驗證的請求來繞過檢查
  5. session 劫持：重複使用別人的 session

🔹 防禦重送封包的方法

🛡️ 防護策略：

1️⃣ CSRF Token（跨站請求偽造令牌）

<!-- 在表單中加入 CSRF Token --> <form action="/vote" method="POST"> <input type="hidden" name="csrf_token" value="隨機產生的Token"> <button type="submit">投票</button> </form> // 伺服器驗證 if ($_POST['csrf_token'] !== $_SESSION['csrf_token']) { die('Invalid token'); }

2️⃣ Nonce（一次性數字）

// 產生唯一的 nonce $nonce = bin2hex(random_bytes(16)); $_SESSION['nonce'] = $nonce; // 驗證並刪除（只能用一次） if ($_POST['nonce'] === $_SESSION['nonce']) { unset($_SESSION['nonce']); // 用完就刪除 // 處理請求... } else { die('Invalid or expired nonce'); }

3️⃣ 時間戳記驗證

// 檢查請求時間 $timestamp = $_POST['timestamp']; $current_time = time(); // 只接受 5 分鐘內的請求 if (($current_time - $timestamp) > 300) { die('Request expired'); }

4️⃣ 記錄已處理的請求

// 使用 Redis 記錄已處理的請求 ID $request_id = $_POST['request_id']; if ($redis->exists("processed:$request_id")) { die('Request already processed'); } // 處理請求後記錄 $redis->setex("processed:$request_id", 3600, '1'); // 1小時後過期

5️⃣ SameSite Cookie 屬性

// 設定 Cookie 時加上 SameSite 屬性 setcookie('session_id', $value, [ 'httponly' => true, 'secure' => true, 'samesite' => 'Strict' // 防止跨站請求 ]);

💥 暴力破解攻擊（Brute Force Attack）

🚨 什麼是暴力破解？
攻擊者使用字典檔（常見帳號、密碼清單）或窮舉法（嘗試所有可能組合），不斷嘗試登入直到成功。這是最常見也最有效的攻擊方式之一！ 高危險

1️⃣ 準備字典檔

⬇️

測試字典檔中的每個帳號密碼組合
⬇️
4️⃣ 成功登入

🔹 防禦暴力破解的方法

🛡️ 防護策略（多層防禦）：

1️⃣ 帳號鎖定機制

// 失敗 5 次就鎖定 15 分鐘 $max_attempts = 5; $lockout_time = 900; // 15分鐘 if ($failed_attempts >= $max_attempts) { $_SESSION['locked_until'] = time() + $lockout_time; die('帳號已鎖定，請 15 分鐘後再試'); }

2️⃣ 速率限制（Rate Limiting）

// 每個 IP 每分鐘最多 10 次嘗試 $redis->incr("login_attempts:$ip"); $redis->expire("login_attempts:$ip", 60); $attempts = $redis->get("login_attempts:$ip"); if ($attempts > 10) { die('請求過於頻繁，請稍後再試'); }

3️⃣ CAPTCHA 驗證碼

// 失敗 3 次後要求驗證碼 if ($failed_attempts >= 3) { // 顯示 Google reCAPTCHA if (!verify_recaptcha($_POST['g-recaptcha-response'])) { die('驗證碼錯誤'); } }

4️⃣ 漸進式延遲

// 每次失敗增加等待時間 $delay = min($failed_attempts * 2, 30); // 最多30秒 sleep($delay);

5️⃣ 兩步驟驗證（2FA）

// 即使密碼正確，還需要驗證 OTP if (verify_password($password)) { // 要求輸入手機收到的驗證碼 require 'otp_verification.php'; }

6️⃣ IP 黑名單

// 將攻擊 IP 加入黑名單 if ($failed_attempts > 20) { add_to_blacklist($ip); send_alert_to_admin("Possible brute force from $ip"); }

📖 多層防禦策略
單一防護措施不夠，需要多層防禦來保護系統。結合各種技術和最佳實踐才能有效防止攻擊。

🔹 防護層級

🏰 七層防禦架構

層級 防護措施 說明
網路層 防火牆、DDoS 防護 阻擋惡意流量和 IP
應用層 WAF（Web 應用防火牆） 偵測和阻擋常見的 Web 攻擊

🔹 完整的登入防護範例

💎 最佳實踐：安全登入系統

// PHP 完整的安全登入範例 <?php session_start(); require 'db.php'; // 1. CSRF 保護 if ($_POST['csrf_token'] !== $_SESSION['csrf_token']) { die('CSRF token mismatch'); } // 2. 速率限制檢查 $ip = $_SERVER['REMOTE_ADDR']; $attempts = $redis->get("login_attempts:$ip") ?? 0; if ($attempts > 10) { http_response_code(429); die('Too many requests'); } // 3. 帳號鎖定檢查 $username = $_POST['username']; $locked_until = $redis->get("locked:$username"); if ($locked_until && time() < $locked_until) { die('Account locked. Try again later.'); } // 4. 驗證碼檢查（失敗3次後） $failed_count = $redis->get("failed:$username") ?? 0; if ($failed_count >= 3) { if (!verify_captcha($_POST['captcha'])) { die('Invalid captcha'); } } // 5. 輸入驗證 $username = filter_var($username, FILTER_SANITIZE_STRING); $password = $_POST['password']; if (strlen($username) < 3 || strlen($password) < 8) { die('Invalid input'); } // 6. 使用 Prepared Statement 查詢 $stmt = $pdo->prepare("SELECT * FROM users WHERE username = ?"); $stmt->execute([$username]); $user = $stmt->fetch(); // 7. 驗證密碼（使用 bcrypt） if ($user && password_verify($password, $user['password_hash'])) { // 登入成功 $_SESSION['user_id'] = $user['id']; // 清除失敗記錄 $redis->del("failed:$username"); $redis->del("login_attempts:$ip"); // 重新產生 Session ID（防止 Session Fixation） session_regenerate_id(true); // 記錄成功登入 log_login_success($user['id'], $ip); header('Location: dashboard.php'); } else { // 登入失敗 $failed_count++; $redis->setex("failed:$username", 3600, $failed_count); // 增加 IP 嘗試次數 $redis->incr("login_attempts:$ip"); $redis->expire("login_attempts:$ip", 60); // 失敗 5 次鎖定帳號 if ($failed_count >= 5) { $redis->setex("locked:$username", 900, time() + 900); send_alert($username, 'Account locked due to failed attempts'); } // 漸進式延遲 sleep(min($failed_count, 5)); // 記錄失敗嘗試 log_login_failure($username, $ip); die('Invalid credentials'); } ?>

🔹 密碼安全最佳實踐

❌ 不安全的密碼處理

// 明文儲存（極度危險！） INSERT INTO users (password) VALUES ('123456'); // 使用 MD5（已被破解） $hash = md5($password); // 沒有 salt 的 SHA1 $hash = sha1($password);

✅ 安全的密碼處理

// 使用 bcrypt（推薦） $hash = password_hash( $password, PASSWORD_BCRYPT, ['cost' => 12] ); // 驗證密碼 if (password_verify($password, $hash)) { // 登入成功 }

🔹 監控和警報系統

📊 需要監控的指標：

  • 登入失敗率：異常高的失敗率可能是暴力破解
  • 請求頻率：短時間大量請求可能是攻擊
  • 異常 IP：來自可疑地區或已知惡意 IP 的請求
  • 錯誤率：異常的 400、500 錯誤
  • 異常行為：深夜大量操作、爬取敏感資料等

🚨 警報機制：

// 偵測異常並發送警報 if ($failed_attempts_per_minute > 50) { send_alert([ 'type' => 'brute_force_detected', 'ip' => $ip, 'attempts' => $failed_attempts_per_minute, 'timestamp' => date('Y-m-d H:i:s') ]); // 自動封鎖 IP add_to_blacklist($ip, 3600); // 封鎖 1 小時 }

🤖 AI 時代的 HTTP 安全防護

⚠️ AI 產生程式碼的安全風險
當你使用 AI（ChatGPT、Claude、Copilot）產生 HTTP 相關的程式碼時，AI 可能會忽略重要的安全措施。你必須學會檢查和補強！

🔹 AI 常見的安全疏忽

❌ AI 可能產生的不安全程式碼

// 範例：AI 產生的簡單登入 <?php $username = $_POST['username']; $password = $_POST['password']; // 問題 1：SQL Injection 漏洞 $query = "SELECT * FROM users WHERE username='$username' AND password='$password'"; // 問題 2：明文儲存密碼 // 問題 3：沒有速率限制 // 問題 4：沒有 CSRF 保護 // 問題 5：沒有輸入驗證 if (mysqli_num_rows($result) > 0) { echo "登入成功"; } ?>

  • 敏感資料處理

[貼上程式碼]」
